# TESTING.md — как пользоваться и тестировать Chatty локально

Живой стенд: фронт **http://localhost:3001**, API **http://localhost:8000**.
Если фронт не отвечает — поднять: `npx vite --mode own --port 3001 --strictPort`
(стек бэкенда обычно уже работает в Docker; если нет — см. `docs/deployment/own-backend.md`).

## Тестовые пользователи

| Email | Пароль | Для чего |
| --- | --- | --- |
| `manual.smoke2@example.com` | `ManualSmoke-2026` | Основной тестовый аккаунт: обычные чаты, P2P, группы, AI-чаты |
| `p2p.peer.smoke@example.com` | `P2p-Peer-2026x` | Второй собеседник для проверки переписки «в обе стороны» |
| `demo.anna@example.com` | `Demo-User-2026` | Участник групповых чатов |
| `demo.boris@example.com` | `Demo-User-2026` | Участник групповых чатов |
| `demo.vera@example.com` | `Demo-User-2026` | Участник групповых чатов |
| `bot@chatty.local` | `BotAccount-2026pass` | Служебный аккаунт бота (отвечает в AI-чатах; логиниться не нужно) |

Прочие юзеры в базе (`smoke-*`, `authsmoke-*`, `live-*`) — мусор автоматических
прогонов, пароли к ним не сохранены.

## Как создать чат с AI

1. Войти (`manual.smoke2@example.com` / `ManualSmoke-2026`).
2. Навести на первый пункт списка чатов (карандаш) → поле «type chat name» →
   ввести название → **Create**. Это обычный чат — AI включается шагом 3.
   AI-чат создаётся там же, но с галкой/флагом `is_ai` через UI ассистента
   (страница `/assistant` — «создать AI-чат») либо чат уже помечен ✦ AI.
3. Открыть чат со значком **✦ AI** (например `unread-ai-demo`, `ai-live-smoke`).
4. Написать вопрос в поле отправки → Enter. Ответ появится сообщением бота
   (фамилия `bot@chatty.local`, пузырь на левой стороне).
   Если модель недоступна — в чат придёт системное сообщение
   «⚠ Ассистент недоступен (…)».

## Как создать чат с одним пользователем (P2P)

1. Войти как `manual.smoke2@example.com`.
2. Создать чат (как выше) с любым названием.
3. Открыть его → в шапке мессенджера кнопка **«+»** (cross) → модалка
   «Добавить пользователя».
4. Начать вводить email второго пользователя **без @** (например `p2p.peer`) —
   поиск сработает сам, символ `@` ввести не получится.
   Уже добавленные помечены бейджем «уже в чате» и недоступны для повтора.
5. Кликнуть по результату → «Пользователь добавлен».

## Как создать групповой чат

1. Создать чат (шаги как в P2P).
2. Через ту же модаль «+» добавить **нескольких** пользователей:
   `demo.ann`, затем `demo.bor`, `demo.ver` — по одному на поиск.
3. Аватары всех участников видны в шапке чата; у каждого участника чат
   появится в списке после обновления страницы (CDM).

## Как протестировать на одном компьютере

Два независимых окна — два разных пользователя:

- **Обычное окно + приватное (инкогнито)**: в первом войти
  `manual.smoke2`, во втором `p2p.peer.smoke`. Открываете один и тот же чат —
  сообщения, реакции и цитаты видны у обоих в реальном времени (WebSocket).
- Или **два разных браузера** (Chrome + Firefox).

Что проверять живьём:

1. **Переписка**: A пишет → у B сообщение появляется без перезагрузки; и наоборот.
2. **Реакции**: наведение на пузырь → кнопка-смайл → выбор эмодзи. Чип под
   пузырём: у поставившего подсвечен, у второго — нет; клик по чипу снимает.
3. **Цитата**: стрелка-«ответить» на пузыре → превью над полем ввода →
   отправка → у обоих в пузыре блок «В ответ …».
4. **Непрочитанные**: B пишет 2-3 сообщения → у A на чате пилюля с числом;
   открытие чата гасит счётчик.
5. **Удаление чата**: владелец (кто создал) → кнопка-крестик в шапке →
   подтверждение; у второго участника открытая панель сама вернёт к списку.
6. **Мобильная вёрстка**: сузить окно <768px — список и чат переключаются,
   кнопка «назад» в шапке; 375px — без горизонтального скролла.
