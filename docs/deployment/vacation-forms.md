# Заявления на отпуск: настройка и обновление (AI-ассистент)

Бот оформляет три заявления по шаблонам RTF и присылает готовый файл
вложением в чат: «заявление на отпуск», «заявление о переносе отпуска»,
«заявление на отпуск за свой счёт». Документация оператора; про график
отпусков — `docs/deployment/vacation-schedule.md`.

## Что заполняется автоматически, что спрашивается

- **Автоматически из графика** (после его ингеста): ФИО (подтверждённая
  фамилия из диалога, см. vacation-schedule.md), периоды отпуска и
  **должность** — первый столбец графика.
- **Спрашивается в диалоге**: фамилия (если ещё не сохранена; те же
  подсказки/уточнения, что у дат отпуска), новые даты для «переноса»,
  даты и дни для «за свой счёт», своя дата для «на отпуск» (если даты из
  графика не подходят). Перед генерацией бот всегда показывает сводку и
  ждёт «да».
- **Никогда не спрашивается**: подпись — линия остаётся пустой, файл
  нужно скачать, проверить и подписать.

## Реквизиты шапки (обязательные env-переменные)

В шапке каждого заявления — организация и адресат. Реквизиты задаются
переменными окружения api-контейнера (compose env; реальные значения в
репо НЕ хранятся):

```
CHATTY_VACATION_ORG_NAME=ООО «Пример»
CHATTY_VACATION_ADDRESSEE_NAME=Иванову И.И.
```

Если хотя бы одна не задана, бот вежливо отказывается оформлять
заявление со ссылкой на этот файл — состояние диалога не создаётся.
После изменения переменных перезапустите api (`docker compose ... up -d api`
или `restart api`).

## Шаблоны

Три шаблона лежат в репо: `backend/app/vacations/templates/`
(`vacation_application.rtf`, `vacation_transfer.rtf`, `unpaid_vacation.rtf`).
Это санитизированные копии оригиналов: реквизиты и заполняемые поля
заменены на `{{плейсхолдеры}}`, служебные метаданные автора удалены.
Набор плейсхолдеров для каждой формы зафиксирован в
`backend/app/vacations/forms/registry.py` и проверяется тестами.

### Как обновить шаблон (изменилась форма от HR)

1. Откройте соответствующий файл из `backend/app/vacations/templates/`
   в Word/LibreOffice.
2. Отредактируйте текст, СОХРАНЯЯ все `{{плейсхолдеры}}` без изменений
   (список — в `registry.py`; удалять/переименовывать их нельзя — рендер
   откажется работать, а тесты упадут).
3. Сохраните файл как RTF в тот же каталог с тем же именем.
4. Прогоните тесты: из `backend/` —
   `./.venv/Scripts/python.exe -m pytest -q tests/unit/vacations` —
   golden-тесты сверят структуру шаблона.
5. Закоммитьте: шаблон — это код, версия tracked в git (откат = revert
   коммита).

Если HR прислала совершенно новую форму — это новый шаблон + запись в
`registry.py` (+ при необходимости новые плейсхолдеры) — задача для
разработки, а не операторская операция.

## Проверка после изменений

1. Тесты: `PYTHON_BIN=<backend-venv-python> bash backend/verify.sh` — всё
   зелёное, кроме 4 известных POSIX-only падений ингеста (как обычно).
2. Живой диалог: в AI-чате «оформи заявление на отпуск» → подтвердить
   период → «да» → сообщение с файлом «Заявление на отпуск — <ФИО>.rtf»;
   скачать и открыть в Word: реквизиты, должность, даты, подпись пустая.

## Откат

Изменения шаблонов/кода — `git revert` соответствующего коммита. Данные
диалогов (assistant_dialog_state.payload) совместимы в обе стороны:
колонка nullable, старый код её игнорирует; при необходимости миграция
`alembic downgrade 015_vacations` снимает колонку целиком.
