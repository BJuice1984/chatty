## Что ещё не сделано

Frontend пока не подключён к собственному backend на уровне полного приложения.
Статическая страница открывается, но legacy API-код ожидает Practicum routes:

| Legacy frontend | Owned backend |
| --- | --- |
| `/auth/signin` | `/auth/login` |
| `/auth/signup` | `/auth/register` |
| `/auth/user` | `/auth/me` |

Поэтому не считать успешное открытие `3000` доказательством полного browser
auth/chat/file/WS flow. Это задача API cutover/adapters.

Публичный production release не заявлен: нет TLS/reverse-proxy, production
firewall, backup/rollback runbook на VM, production cookie policy и release
observability. Текущий стенд — внутренняя проверочная VM.

authorized. Он описывает Practicum/own adapters, composition root, frontend
auth/chats/profile APIs, WS gateway и smoke обоих режимов. Его manifest зависит
от `2026-09-28-migrate-chats-profile`, `backend-skeleton` и
`backend-chats-ws-files`; не начинать реализацию draft напрямую.

По текущей дорожной карте frontend-последовательность: `kernel-router-store` →
`module-kernel-guard-v2` → `migrate-chats-profile` → `api-cutover`. Перед новым
worker-run нужен актуальный baseline `dev`, независимый plan audit, freeze,
worker packet и отдельный PR в `dev`. Если пользователь хочет сделать cutover
непосредственно следующим пакетом, сначала нужно явно пересмотреть зависимости,
ownership и acceptance, затем refreeze через ALK.

Локальную модель не использовать для ревью планов. Её reachability/configuration
проверяется отдельным будущим gate перед RAG/bot; текущий frontend/backend smoke
от неё не зависит.
