# ИИ-ассистент

ИИ-контур Chatty: бот-участник в AI-чатах, RAG-поиск по документам,
отпускные скиллы (даты графика + генерация RTF-заявлений) и LLM-автоназвание
чатов. Всё работает на **локальных моделях** (Ollama: `qwen3:14b` — генерация,
`nomic-embed-text` — эмбеддинги); данные не покидают контур.

## Конвейер ответа: durable-раны (`services/bot.py`, `models/bot_run.py`)

Триггер — сообщение пользователя в чате с `is_ai=true`: фронт после отправки
зовёт `POST /chats/{id}/bot/runs {message_id}`.

Один ран на сообщение (`unique(message_id)`), исполнение **долговечно**:

1. **Гварды** — активное членство запросившего, `is_ai` чата, не своё
   сообщение бота.
2. **Клейм CAS-переходом** (коммит до внешних вызовов): дубль доставки не
   создаёт второе исполнение; жёсткий краш оставляет наблюдаемый
   `queued`/`running`. `failed`-ран ретраится (бюджет `max_attempts`),
   зависший `running` старше `stale_after_seconds` реклеймится.
3. **Цепочка скиллов** (детерминированные ветки ДО LLM, порядок важен):
   1. **Визарды заявлений** (`vacations/forms/skill.py`) — активный визард
      владеет диалогом;
   2. **Отпускной скилл дат** (`vacations/skill.py`) — offer/фамилия/ответ;
   3. **RAG + LLM** — общий путь.
   Каждый скилл может ответить сам, передать изменённый вопрос дальше
   (`passthrough_question`) или отказаться (`None`).
4. **Постинг ответа** — через контракт сообщений (та же авторизация файлов),
   `run.status='succeeded'`, ссылка на сообщение-ответ и вложение.
   Перед постингом и рассылкой флаг `is_ai` перечитывается — выключение
   бота во время генерации не тратит инференс и не показывает ответ.

Статусная машина видна оператору в БД: `queued → running → succeeded |
failed(+error_kind)`. `error_kind` машинно-читаем (`bot_user_not_configured`,
`bot_disabled`, `embedding_provider_unavailable`, `attachment_not_authorized`,
`form_storage_failed`, …) — это и есть лог аудита исполнений.

## Стриминг ответа

Провайдер умеет `complete_stream` (SSE у Ollama/OpenAI-совместимых).
`CHATTY_BOT_STREAMING=false` — kill-switch к цельному `complete()`;
`CHATTY_BOT_ENABLE_THINKING=false` отключает reasoning-секцию. Сервис
коалесцирует дельты окном ~250 мс и мостит их из worker-потока в event loop
(`run_coroutine_threadsafe`); эндпойнт рассылает `bot_delta {message_id,
delta}` по WS активным членствам. Финальное сообщение несёт полный текст —
дельты чисто прогресс-UI, сбой моста не роняет ран. Фронт вяжет дельты к
pending-хвосту по `pending_for` (один store-эмит на дельту, чужие/поздние
молча дропаются) и показывает CSS-анимацию «печатает».

## RAG: документы и поиск (`services/documents.py`, `ingestion/`)

- **Ингест** (админ): файл из чата → конвертер (`soffice --headless`, для
  legacy-форматов) → парсер (pdf/docx/txt) → чанкинг → эмбеддинги →
  `documents.status='ready'` + `doc_chunks.embedding`. Каждая внешняя
  неудача — явный `failed` с `error_kind`; имя файла участвует в индексе.
- **Поиск**: эмбеддинг запроса → косинусная близость по чанкам `ready`
  документов → top-K (кап `top_k_max`). Библиотека документов общая
  (Scope B), авторизация — членство в чате запускающего рана.
- **Порог релевантности** `rag_min_score`: чанки ниже порога не входят ни в
  промпт, ни во вложения — на посторонний вопрос бот отвечает «информации
  нет», а не ближайшим файлом. Первый релевантный чанк прикладывается к
  ответу как вложение-источник; фронт показывает список найденных
  документов под ответом (шов `setDocumentSearch`).

## Промпты (`bot/prompts.py`, `vacations/prompts.py`)

Граница данных промпта — только system-шаблон, контекст чата и текст
сообщения; ничего больше не входит в запрос к модели.

Системный промпт RAG-ассистента (контекст чанков нумеруется и вливается в
тот же system-блок — два подряд system-сообщения роняют jinja-шаблон Qwen):

```
You are the Chatty assistant. Answer using the document context
provided below when it is relevant; you only ever see context from
this chat. Answer concisely in the language of the question.

Document context from this chat:

[1] <чанк 1>   [2] <чанк 2> …
```

Промпт ответа по графику отпусков — **только структурированные строки
данных, чанки RAG сюда не попадают никогда** (защита от галлюцинаций на
чужих датах):

```
Ты помощник, который отвечает на вопрос о датах отпуска. Отвечай
ТОЛЬКО по строкам данных ниже: не выдумывай и не добавляй даты,
обращайся к пользователю по имени из данных, отвечай кратко и по-русски.
```
```
Даты отпуска из графика:
<строки «ФИО — с DD.MM.YYYY на N дней»>
```

Промпт LLM-автоназвания чата (`TITLE_SYSTEM_PROMPT`; «2–4 слова, ровно
NONE, если темы нет» — метка NONE отличает болтовню от появившейся темы).
При отказе провайдера скилл дат падает на шаблонный ответ строками —
пользователь всё равно получает даты.

## Отпускной скилл: даты графика (`vacations/`)

- **Ингест графика** `график отпусков <год>.xlsx` (runbook:
  [deployment/vacation-schedule.md](../deployment/vacation-schedule.md)):
  openpyxl-парсер листов с шапкой «ФИО» (департамент-строки, строковые и
  урезанные даты, год из имени файла) → снапшот `vacation_schedules` +
  строки `vacation_periods`. Реингест того же файла идемпотентно заменяет
  снапшот; ответы всегда из последнего.
- **Интенты** (`intent.py`) — детерминированная классификация: точные
  словоформы (морфология существительного «отпуск» отсекает глаголы
  «отпускает/отпустить»), окно «график × отпуск» и «даты × отпуск»,
  фразы форм заявлений. Никакой LLM-классификации — ветвление
  воспроизводимо и тестируемо.
- **Диалог** (`skill.py`): общий вопрос про отпуск → offer «Хотите узнать
  свои даты?» → «да» → вопрос фамилии (один раз; валидация по графику,
  подтверждённая фамилия хранится в `vacation_names` и переживает
  реингесты) → ответ датами. Отказ возвращает исходный вопрос в RAG-путь.
  Состояние — `assistant_dialog_state` с TTL (висящее «да» ничего не
  связывает), лимит попыток, cancel-фразы.
- **Приватность**: lookup только по сохранённой фамилии пользователя или
  его прямому ответу; промах отвечает «Такой фамилии в графике нет» — без
  перечня сотрудников и похожих фамилий.

## Визарды заявлений (`vacations/forms/`)

Три формы: «на отпуск», «о переносе», «за свой счёт». Конечные автоматы на
`assistant_dialog_state` (`form:<kind>:<step>`, закрытый словарь шагов) с
payload-JSON. Визард спрашивает только то, чего нет в графике (фамилия —
общий UX, должность — если строка графика без неё, даты — если форма
требует), всегда показывает сводку и ждёт «да». Ответы детерминированы —
**ноль LLM-вызовов**; генерация — байт-детерминированная заливка RTF-шаблона
(`templates/*.rtf` с `{{плейсхолдерами}}`, golden-тесты пинят структуру).
Готовый файл загружается в хранилище и приезжает вложением
«Заявление … — <ФИО>.rtf». Реквизиты шапки — env оператора
(`CHATTY_VACATION_ORG_NAME`, `CHATTY_VACATION_ADDRESSEE_NAME`); без них бот
вежливо отказывается, не создавая состояния. Runbook —
[deployment/vacation-forms.md](../deployment/vacation-forms.md).

## Фронтенд-контур

- `/assistant` — страница ассистента; «+AI» в шапке любого чата включает
  бота (PUT `is_ai`); «Чат с AI» — one-click создание
- WS-шлюз чатов слушает `bot_delta` и обновляет pending-хвост;
  `waitForOwnEcho` даёт честную ошибку «эхо не получено» (5с) вместо
  молчаливого зависания; композер разблокируется в `finally`
- Список найденных документов под ответом — шов `setDocumentSearch`
  (RAG-поиск принадлежит фиче ai-assistant)
