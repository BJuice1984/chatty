# Developer overview — 2026-11-08-mobile-messenger-ux

## Зачем

Оператор после влития PR #57 принёс восемь шероховатостей: мобильная
раскладка ломается длинным рядом историй, жесты отсутствуют, кнопки
шапки чата не влезают в мобильную шапку; плюс пять точечных UI-правок
(позиция чипа авто-названия, стрелка пункта настроек, потерявшая
подложку/карандаш прозрачная аватарка, отсутствие подписи автора в
групповых чатах и маркера ответов бота). Прогон закрывает все восемь
и добавляет минимальный бэкенд-маркер бота, без которого AI-плашку
невозможно построить надёжно.

## Что увидит пользователь

- Мобильный: истории больше не выпихивают приложение за экран; из чата
  и из секции настроек можно вернуться свайпом вправо; вьюер историй
  листается свайпами и закрывается свайпом вниз; кнопки шапки чата
  собраны в меню «⋮».
- Везде: чип «авто-название» стоит у левого края заголовка; стрелка
  пункта настроек снова у правого края; карандаш под аватаром настроек
  появляется только при ховере; в групповых чатах над сообщениями виден
  автор (аватар + логин, email в подсказке); ответы бота помечены «✦ AI».

## Архитектурные границы

- Слои как всегда: `pages → components → controllers → api → utils →
  core`. Компоненты не ходят на бэкенд; данные автора и флаг бота
  приходят через существующий стор-срез chatUsers, мэппинг — в
  withStore-мэппере Messenger (mapTypedMessages расширяется параметром
  участников, не ходит в стор сам).
- Новый `src/utils/swipe.ts` — чистый классификатор
  (start, end) → 'left' | 'right' | 'down' | null, без DOM; компоненты
  вешают touchstart/touchend через существующий механизм events Block
  (делегирование с корня, переживает перерисовки).
- Истории: вьюер остаётся презентационным — жест уходит колбэком
  onSwipe(direction), навигация (next/prev/close + маркировка
  просмотра) принадлежит странице chat, как таймер сегодня.
- Кебаб-меню: тот же Modal и те же handleClick-колбэки, что у иконок
  шапки; в дескрипторы кнопок добавляются подписи для меню. Скрытие
  ряда иконок — чистый CSS (<768), DOM остаётся общим.
- Бэкенд: `ChatMemberBrief.is_bot: bool = False`; вычисление — в
  `to_member_brief` (единая точка формы, её уже используют и GET
  /chats/{id}/members, и краткие составы GET /chats), сравнение email с
  `bot_settings_from_env().user_email` — тот же идиом, что в
  services/chats.py:569-571. Ответ-only, alembic не трогаем.

## Риски и как ими управляем

- Layout-баг M1 — гипотеза min-content: фикс (minmax(0,1fr) +
  min-width: 0) безопасен для всех веток; обязательный живой смоук
  390px с 15+ историями до/после.
- Тач-эмуляция в jsdom: changedTouches досыпается в обычный Event;
  классификатор тестируется как чистая функция.
- Повторное использование класса `chat__container-profile-arrow` в
  profile-settings после pack-2 осталось без стилей — меняем на
  собственный класс, старый класс из шаблона убираем.
- Прозрачная svg-аватарка: перенос подложки в :hover — осознанная
  touch-деградация (review F-5): сегодня подложка с карандашом видна
  на touch-устройствах всегда, после переноса аффорданс там исчезает
  полностью (клик/выбор файла остаются) — ровно то, что просил
  оператор (подложка только при ховере).

## Модель исполнения

Два воркстрима, последовательные (parallelism 1):

1. **WS-BE-BOT** — бэкенд-маркер is_bot (схема, билдер, интеграционные
   пины). Гейт: бэкенд-гейт по D-11 (bash backend/verify.sh, всё
   зелёное, кроме ровно 4 известных POSIX-only падений ingestion).
2. **WS-FE-MOBILE** (dependsOn WS-BE-BOT) — весь фронтенд: свайпы,
   кебаб, layout-фиксы, плашки, стили, тесты. Гейт: npm run verify,
   guard --all --strict, живой смоук.
