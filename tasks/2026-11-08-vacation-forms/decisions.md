# Decisions — 2026-11-08-vacation-forms

Операторские решения и решения контроллера с источником. Нумерация D-F-*
(форма), чтобы не конфликтовать с D-1…D-18 прогона 2026-11-08-vacation-skill.
Литералы реальных реквизитов в пакете не приводятся (D-F-16): полный
маркер-набор — work/2026-11-08-vacation-forms/evidence/privacy-markers.md
(локально, гитигнорён).

## Операторские решения (2026-11-08)

- **D-F-0 — автономный мандат.** Оператор: «делай автономно». Покрывает весь
  прогон: составление плана, ревью-циклы, freeze, исполнение, гейты, пуш
  ветки. Блокеры решает контроллер, каждое решение — записывается сюда.
  Живой смоук (EV-4) остаётся за оператором (бот поднят на другой машине
  позже), финальный аудит — BLOCKED до квитка, PR не вливается (зеркалит
  D-3 родительского прогона).
- **D-F-1 — шаблоны в репо, без реквизитов** (выбор оператора из
  AskUserQuestion). Санитизированные RTF-шаблоны с `{{плейсхолдерами}}`
  коммитятся в `backend/app/vacations/templates/`; реальные реквизиты
  шапки заменены на `{{org_name}}` / `{{addressee}}` и подставляются из
  env-настроек. Обновление формы = коммит. Живые RTF-оригиналы остаются
  в гитигнорённом `tasks/RAG-docs/` (read-only источник для деривации).
- **D-F-2 — должность из графика** (коррекция оператора: «Должность в
  графике отпусков есть — первый столбец»). Подтверждено разведкой: A1
  всех листов = «Должность», парсер уже кладёт её в
  `VacationPeriod.position`, ингест пишет (ingest_vacations.py:99).
  `VacationService.find` пока не отдаёт должность наружу — план
  расширяет `VacationPerson.position`. Спрашивать должность у юзера не
  нужно; исключение — грязная строка графика без должности: визард
  спросит её на это одно заявление (без персистенса, редкий случай).
  Исходное предложение «спросить один раз и сохранить» ОТМЕНЕНО
  коррекцией оператора; колонки position в vacation_names не появляется,
  миграция 016 ограничена `assistant_dialog_state.payload`.
- **D-F-3 — автозаполнение дат из графика с подтверждением** (выбор
  оператора). «Заявление на отпуск»: период из графика (один —
  подтвердить; несколько — выбор номером), свои даты — текстом. «Перенос»:
  старый период из графика, новые даты спрашиваются (дни по умолчанию =
  старым). «За свой счёт»: даты всегда спрашиваются (в графике их нет).

## Решения контроллера

- **D-F-4 — ветка стеком.** `feature/2026-11-08-vacation-forms` от
  `feature/2026-11-08-vacation-skill` @ 15b999a (PR родителя не влит,
  D-3 держит до живого смоука EV-4 родителя). Фича требует
  vacation_names/vacation_periods/скилл-хук, ветвление от dev невозможно.
  Если родительский PR вливают раньше — ребейз на dev перед PR этого
  прогона (trivial: тот же контент).
- **D-F-5 — доставка файла вложением чата.** FileService.upload
  (owner = бот-юзер, chat-scoped, RustFS) → MessageCreate(file_id=…) →
  run.attachment_file_id. Фронт не меняется: вложения в сообщениях уже
  рендерятся (file_name в MessageResponse, download у участников).
  Storage-seam инжектится в endpoint (app.state) — поэтому
  `backend/app/api/v1/endpoints/bot.py` становится узко-записываемым
  файлом этого плана (в родительском прогоне app/api был запрещён
  целиком; отклонение обосновано нуждами seams, аудит владения ловит
  всё вне write-set).
- **D-F-6 — детерминированные тексты визарда, без LLM в формах MVP.**
  Вопросы/подтверждения — фиксированные шаблоны: юридически значимые
  строки, повторяемость важнее живости. Гибрид LLM остаётся в ответах
  про даты отпуска (родительский контур). Провайдер формам не нужен.
- **D-F-7 — ФИО в заявлении = каноническая форма из графика** (инициалы,
  «Абрикосов Т.П.») в шапке и в подписи («(ФИО полностью)» — слот
  заполняется той же канонической формой). Полное ФИО в графике
  отсутствует — расширение non-goal.
- **D-F-8 — дата заявления = серверная дата генерации; год = год
  графика** для «на отпуск»/«перенос» (снимок года 2026), текущий год —
  для «за свой счёт». Слот «202___» параметризован в `{{year}}`.
- **D-F-9 — морфология дней: полная фраза.** Токен `{{days_word}}` несёт
  всю согласованную фразу «календарный день / календарных дня /
  календарных дней» из НОВОГО helper'а в forms-модуле
  (calendar_days_word; родительский days_word «день/дня/дней» не трогаем
  — он про ответы чата). Пины 1/2/14 (F-R1-3: согласование прилагательного
  не покрыть одиночным словом — либо терялось «календарн-», либо ломалось
  единственное число).
- **D-F-10 — приватность реквизитов и metadata.** Реальные реквизиты
  шапки (2 маркера), третье реальное ФИО с тегом подразделения из
  `{\info}{\author}` двух исходников и вендор правовой БД из metadata
  двух других — НЕ попадают в репо ни в одном файле. Деривация
  ВЫРЕЗАЕТ группу `{\info}` целиком (структурный пин: в шаблонах нет
  `\info`); маркеры для контрольного grep'а живут только в локальном
  evidence (privacy-markers.md), коммитимые тесты проверяют вымышленные
  аналоги (ООО «Альфа-Тех», Смирнову А.А.). Пуш-гард страхует. (F-R1-2.)
- **D-F-11 — миграция 016 минимальна:** одна колонка
  `assistant_dialog_state.payload` (Text NULL) под JSON данных визарда.
  Состояния визарда — закрытый словарь `form:<kind>:<step>` в существующей
  String(32); самый длинный шаг 'form:vacation:choose_period' = 27
  символов (арифметика исправлена по F-R1-5); юнит-пин перебирает ВСЕ
  объявленные шаги словаря и отказывает на >32, чтобы новый шаг не
  «молча» переполнил колонку.
- **D-F-12 — маршрутизация скиллов.** FormsSkill вызывается ПЕРВЫМ:
  обрабатывает состояния `form:*` и интенты form_*; старт визарда чистит
  чужое dialog-состояние (пивот юзера из awaiting_yes в визард).
  classify() получает form-виды ВЫШЕ schedule/vacation («оформи заявление
  на отпуск» содержит «отпуск» и не должен ловиться предложением дат);
  VacationSkill явным образом пропускает form-виды.
- **D-F-13 — surname-шаг визарда** переиспользует логику родительского
  скилла: выделяется общий helper (поиск/подсказки/2 попытки/отмена/
  сохранение canonical имени), оба скилла его зовут; поведение
  родительского скилла пинится существующими тестами (без изменений
  контракта).
- **D-F-14 — коммиты без co-author-трейлеров** (правило оператора,
  memory no-coauthor-in-commits), conventional commits.
- **D-F-15 — non-goal: заявление на увольнение** — оператор не заказывал;
  интент-классификатор обязан НЕ матчить его в form-виды.
- **D-F-16 — санитизация самого план-пакета** (урок D-18 родителя,
  повторённый в rev 1 и пойманный ревью F-R1-2 + контроллером): в
  черновик пакета попали литералы реальных реквизитов. С rev 2 пакет
  обезличен; маркеры — только в work/evidence/privacy-markers.md.
- **D-F-17 — флейк базового гейта.** Первый полный прогон базы дал 5-е
  падение `test_social_api::test_replies_validation_snippet_and_ws_contract`
  (WS-сниппет) — в изоляции и файлом зелёный, второй полный прогон чист
  (392 passed / ровно 4 известных ingestion-падения, цифры родителя).
  Контракт гейта не меняется; оба вывода — в evidence (base-gate.txt,
  base-gate-2.txt); тест вне write-set этого плана.
- **D-F-18 — RTF-профиль эскейпов и слоты дат** (feasibility-проб
  контроллера до freeze + независимое подтверждение ревью F-R1-1/F-R1-7;
  проб вскрыл: Word открыл заполненный файл, значения корректны).
  Оригиналы сгенерированы r7-office: `{\rtf1\ansi\ansicpg0}` и ВЕСЬ текст
  (кириллица, цифры, точки, пробелы, подчёркивания) — `\uNNNN*`-эскейпы
  (десятичный \u + байт-фолбэк `*`); `\'hh`-байт ноль. Поэтому: (а) рендер
  значений выдаёт `\uNNNN*`-эскейпы — интерпретация не зависит от
  кодовой страницы читателя; (б) поиск реквизитов при деривации ведётся
  по полностью-эскейпнутым формам; (в) кластер «\_\_\_\_.\_\_\_\_\_\_ 202\_\_
  г.» сворачивается целиком в «{{start_date}} {{year}} г.» — {{start_date}}
  = ДД.ММ без года (проб показал дубль года при полном дате), {{today}} =
  ДД.ММ.ГГГГ; (г) подчёркивания — consecutive `\u95*`-раны, разбитые
  формат-группами RTF — деривация маппит раны позиционно.
- **D-F-19 — границы форм-интентов и рестарт визарда** (F-R1-4/F-R1-8/F-R1-9):
  (а) ключевые слова — точные словоформы по границам слов, БЕЗ
  префиксного/стем-матчинга; form_vacation триггерится
  заявление-ключами (словоформы «заявление/заявления» явным перечнем) —
  императивы «оформи/оформите» и инфинитив «оформить» самостоятельными
  триггерами НЕ являются, иначе ломается родительский пин «Как
  оформить отпуск?» → vacation (F-R2-3); (б) unpaid-триггеры — составные корроборированные
  фразы («свой счёт», «за свой счёт», «без сохранения зарплаты/заработной
  платы», «без содержания» + отпускной контекст), голый «счёт» и
  биллинговые фразы — не триггер; «нужен/хочу отпуск» без
  заявление-ключей — vacation, не form; (в) форм-интент ДРУГОГО вида в
  активном form-состоянии — рестарт визарда нового вида с чистым payload;
  того же вида — повтор текущего шага.

- **D-F-20 — маршрут замыкания хвоста F-R2-4 при фризе.** Ревью r3: READY_TO_FREEZE с одной открытой minor (две иллюстративные опечатки «\uu95*»/«\uu1040*» в REQ-TEMPLATES/REQ-RTF; авторитетные формулировки профиля побайтово точны, воркер-поверхности от них не зависят). Обе правки вмержены в обязательный freeze-flip-эдит этого ревизии (status FROZEN + блок planReview байты меняет в любом случае), digest пересчитан и подложен в plan-review.json до lock-create (протокол hash родительского r3).
