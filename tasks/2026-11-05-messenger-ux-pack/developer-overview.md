# Developer overview — 2026-11-05-messenger-ux-pack

## What the user gets

- Свежесозданный чат появляется ВЕРХОМ списка (сортировка по активности с fallback на
  created_at), а не тонет вниз без сообщений.
- Смена аватара чата живёт в шапке открытого чата (слева от названия, слот бывшего отступа
  77px) и доступна владельцу; карточка списка больше не притворяется кнопкой с карандашом.
  Длинные названия аккуратно эллипсятся.
- Двойной клик по названию — inline-переименование; Enter, Escape или клик вне сохраняют,
  пустой ввод откатывает. В ленту падает служебная строка «X переименовал чат в «Y»» с
  временем; у других участников и заголовок списка обновляется сам (WS).
- «Найти все чаты» в меню контакта включён: ведёт в мессенджер с сидом `@email` в поиске и
  показывает все общие чаты; ручной ввод `@` в поиске чатов ищет по участникам.
- Удаление участника и собственный выход снова работают: живой контейнер API пересобран со
  всеми слитыми роутами (ничего в коде не менялось — контейнер был старее репозитория).
- Иконка в шапке списка (бывшие «настройки») помечает ВСЁ прочитанным; без непрочитанных она
  потушена и некликабельна.

## Execution model

Четыре волны, DAG: `WS-BE-API` → (`WS-OPS-STACK` | `WS-FE-CHAT`) → `WS-FE-SEARCH`.
maxParallelTasks = 1 — фактически последовательные. WS-OPS-STACK пишет в репо только
`scripts/probe-own-backend-routes.ps1` (пробы 401-vs-404 + health), остальное его evidence —
журнал пересборки и smoke-транскрипт. Все волны на одной ветке
`feature/2026-11-05-messenger-ux-pack`, PR в `dev` после финального аудита.

## Key integration seams

- **System message**: `messages.kind` (NULL = обычное). Тот же контракт проходит через REST
  history, WS 'message' и MessageResponse — рендер-ветка на Message-компоненте (служебная
  строка вместо пузыря). Контент строит сервер; клиентское экранирование — как у любого
  сообщения (двойные скобки).
- **chat_renamed**: новый тип WS-события (fan-out активным), слушатель — consumer-side в
  контроллере chats через gateway-notify (паттерн onReaction/onChatDeleted).
- **contacts → chats**: `setChatSearchOpener` в contacts-контроллере (default noop), связка в
  `features/index.ts`: сид searchBar-памяти + `ChatsController.searchChats` + `Router.go`.
- **read-all**: один bulk-upsert в репозитории, семантика повторяет `unread_counts`
  (все членства, включая архивные); фронт гасит пилюли локально.

## Risks / edges

- Миграция 012 аддитивна; сегментные тесты 009/010/011 штампуют `head` — с 012 их downgrade
  прогоняет и 012; изоляция держится явными таргетами, репин — только если прогон покажет
  нарушение ассертов.
- Живой пересборкой управляет runbook: preflight → build → health/ready → пробы; откат
  описан там же. Оллама-хост не нужен для этого контура.
- Escape-сохранение — осознанное решение оператора (не «отмена»), закреплено уточнением.
- unread у системного сообщения для остальных участников — принято (событие ленты).
- `searchChats` с сидом `@email`: уникальность email даёт точное множество общих чатов;
  ручной `@префикс` может поймать одноимённых — задокументировано.
