Roadmap alias: `api-cutover`; ALK package id: `2026-09-28-api-cutover`. Create `feature/2026-09-28-api-cutover` from the accepted `dev` baseline `dev@66b2d4496120f3af15fd20defb8b6f5d6165b93c` (stage 4 merge, PR #19) and open its PR into `dev`; backend stages 5–6 are already contained in it.

Own the frontend adapter layer for Practicum and the owned backend: `features/auth|chats|profile/api/{practicum,own,index}.ts` behind the unchanged feature ports, the chat WebSocket gateway `features/chats/ws/{practicum,own,gateway}.ts` replacing the legacy `MessagesController`, mode-selected port wiring in the composition root (`src/features/index.ts`), and the shared message renderer with safe attachment URLs. Prove both modes and a clean WS close before calling the cutover complete.

Revision 2 reconciles the draft with the post-stage-4 tree. The composition root is no longer created here (stage 4 did): `src/main.ts` stays untouched (readOnly + forbidden) and `src/features/index.ts` is only edited to select mode-specific ports. This stage owns the legacy teardown stage 4 explicitly deferred: deletion of `src/api` (AuthApi, BaseApi, ChatsApi, UserApi, plus the consumer-less errors.ts) and `src/controllers/MessagesController.ts`, the `Message` DTO re-home into `src/utils/types.ts` (this closes the last `TRANSITIONAL_DEBT` Store.ts entry in the guard map), an own-mode CSRF cookie reader (`src/utils/csrf.ts`: `chatty_csrf` double-submit against `env.csrfHeaderName`, refresh retry-once for own `/auth/me`), and the chats user-search move from a direct legacy `UserApi` call into `ChatsPort` (the one port edit; stage 4 had to borrow the legacy API directly). `sendMessage` is threaded from the chat page through props so components no longer import the controllers layer at all.

Own-mode adapters cover the backend contract that exists — auth register/login/refresh/logout/me, chats create/list/members, files upload/download, WS `message`/`history` events with cookie auth and origin checking — and reject the rest with explicit unsupported-mode errors; practicum adapters preserve current endpoint behaviour byte-for-byte behind the same ports. Own-mode credentials are mapped explicitly: `SignInRequest.login` becomes the backend `email` on signin, register sends `SignUpRequest.email`, and `UserResponse` (id/email/role/is_active/created_at only) maps onto `AuthUser` with `login`=`display_name`=`email` and empty name/phone/avatar defaults. The login/register form validators stay practicum-calibrated (login charset without `@`, password 8–40 vs the owned backend minimum 12), so the own-mode smoke drives the feature ports/controllers directly at console level; that UI limitation is recorded, and adapting form credential policy is out of scope for this stage. Deletions land only after replacement paths compile. Feature domain files (guard, modules, stores, other ports) belong to stages 3–4 and stay untouched.

Both runtime modes are compatibility targets, not production environments. External backend/Docker availability is recorded as bounded evidence and never hidden.
