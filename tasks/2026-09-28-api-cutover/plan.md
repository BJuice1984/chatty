# Implementation plan

1. Re-home the `Message` DTO into `src/utils/types.ts`, add `searchUsers` (chats-local `ChatsUserSearchResult` type, ports stay import-free) to `ChatsPort`, and add the own-mode CSRF cookie reader `src/utils/csrf.ts` with `csrf.test.ts` (double-submit `chatty_csrf` against `env.csrfHeaderName`).
2. Implement `features/auth|chats|profile/api/practicum.ts` by moving the current legacy-`src/api` adapter code over `HTTPTransport` with `env` URLs, then `own.ts` against the owned backend contract and `index.ts` selecting by `env.mode`. Own auth: `SignInRequest.login` maps to the backend `email` field, register uses `SignUpRequest.email`, refresh retry-once on `TransportError` status 401 for `/auth/me`, and `UserResponse` (id/email/role/is_active/created_at only) maps onto `AuthUser` with `login`=`display_name`=`email` and empty names/phone/avatar defaults. Own chats supports exactly fetchChats/createChat/addUsers plus the empty-token `getToken` sentinel for the cookie-auth WS (with `ChatResponse`→`ChatInfo` mapping: `avatar`='', `unread_count`=0); getChatUsers, searchUsers (no backend endpoint), deleteChat, removeUsers, changeChatAvatar and all profile operations reject with explicit unsupported-mode errors.
3. Implement `features/chats/ws/{gateway,practicum,own}.ts` as the `ChatMessagesPort` replacement of `MessagesController`: practicum token-URL flow vs own cookie-auth flow (`joinUrl(wsUrl, /ws/chats/{chatId})`), `message`/`history` event mapping (`MessageResponse` `created_at`→`time`, `content`/`file_id` handling) onto the store `messages` slice, clean close with `closeAll()` observable by the smoke flow.
4. Rewire the three feature controllers to the mode-selected ports, edit the composition root `src/features/index.ts` accordingly, thread `sendMessage` from the chat page (`chat.ts` + `chat.hbs`) through messenger props, and pass the computed safe attachment URL through `messenger.ts` and the `messenger.hbs` helper hash into the shared message renderer (`message.ts`/`message.hbs`). Update the affected boundary tests (chats, profile, new adapter/gateway/csrf tests).
5. Delete `src/api/{AuthApi,BaseApi,ChatsApi,UserApi,errors}.ts` and `src/controllers/MessagesController.ts` only after the replacement paths compile; remove the last `TRANSITIONAL_DEBT` Store.ts entry from the guard map and refresh the stale stage-4 comment block in the same script; confirm no import of a deleted path remains.
6. Run deterministic verify/build/guard (`--all --strict`, zero debt expected) and the three bounded smoke flows: Practicum login, own auth/chat/file, and clean WS close. The own-mode runtime uses the committed `.env.own.example` copied to a gitignored `.env.own` (vars: `mode=own`, api/ws/files URLs, `X-CSRF-Token`) and is served with `npm run dev -- --mode own`. Own-mode smoke drives the feature ports/controllers directly at console level: the login/register form validators stay practicum-calibrated (login charset without `@`, password 8–40 vs the owned backend minimum 12), which is a recorded UI limitation, not a hidden failure; adapting form credential policy is out of scope for this stage. Only after both modes pass may the package be accepted.
