# Developer overview — 2026-11-06-llm-chat-autotitle

## Intent и видимый результат

Новые чаты сегодня рождаются безликими: one-click чат — сид «Чат с» (плюс
дописанные имена участников), AI-чат — «AI ассистент», и несколько таких чатов
в списке неразличимы. Фича: после короткого обмена репликами локальная модель
(Qwen3.5-9B, тот же инстанс, что у бота) **один раз** читает диалог и даёт
короткое название. После этого `auto_titled` гасится навсегда — заголовок
финализируется (инпут → статичный h2), дальше только ручной dblclick rename.
Действует для ВСЕХ новых auto_titled-чатов: и пользовательских, и AI.

## Почему порог по юзерским репликам, а не «ждать длинное сообщение»

Длина одного сообщения не коррелирует с информативностью («Привет! Как у тебя
дела, давно не общались, чем занимаешься?» — длинно и пусто). Решение —
аккумулятор: **гейт считает только реплики людей** (бот-ответы развёрнуты и
раздули бы счётчик после первого «привета»; системные строки не считаются
вовсе): ≥ 2 реплик и ≥ 120 символов суммарно. Приветственный обмен
(«Привет, как дела?» = 16 символов) до модели не доходит. Второй слой —
явный отказ модели: промпт разрешает ответить ровно `NONE` («темы нет»),
что оставляет флаг живым и даёт естественный ретрай на следующем сообщении.

## Архитектура

Поток: **юзерское сообщение → любая из двух точек входа — WS router
(`app/ws/router.py`, event `message`) или HTTP POST `/chats/{id}/messages`
(путь askBot страницы AI-ассистента) → fire-and-forget задача автотайтла**
(общий планировщик `app/ws/autotitle.py`: per-process in-flight set →
`asyncio.to_thread` на свежей сессии → сервис → при успехе
`hub.broadcast('chat_renamed')` активным участникам). Обе точки — реальные
прод-пути фронта: композер мессенджера шлёт через WS, форма ассистента —
через HTTP (план-ревью F-1). Отправка сообщения никогда не ждёт модель.

Слои:

- `app/bot/config.py` — новый `AutoTitleSettings` + `autotitle_settings_from_env()`
  (CHATTY_AUTOTITLE_ENABLED/MIN_USER_MESSAGES/MIN_USER_CHARS/CONTEXT_MESSAGES/
  CONTEXT_CHARS/TIMEOUT_SECONDS/MAX_TITLE_CHARS/MAX_CHAT_MESSAGES). Провайдер
  и модель — ботовские (CHATTY_BOT_*), второго стека нет.
- `app/bot/provider.py` — опциональный `complete_short(messages, *, max_tokens,
  timeout_seconds)`: Ollama — `think:false` + `options.num_predict`;
  OpenAI-совместимый — `max_tokens` + `chat_template_kwargs.enable_thinking:false`
  (ручка уже существует в `_request_body`); таймаут — параметр через общий
  `_provider_timeout` (бюджет ручки доезжает до короткого пути, фолбэк
  `complete()` остаётся на провайдерском). Сервис зовёт его через
  `getattr`-фолбэк на `complete()` — scripted-фейки бото-тестов не ломаются
  (прецедент: `complete_stream` в `BotService._answer`).
- `app/services/chat_autotitle.py` — ЧИСТЫЙ синхронный сервис: гейт → сборка
  контекста (последние 10 kind-NULL непустых сообщений / кап 2000 символов,
  роли `user`/`bot` по `bot_user_id`) → вызов модели → гигиена ответа (strip,
  снять кавычки и хвостовую точку, отвергнуть пустое/NONE/многострочное/
  длиннее 48) → **CAS**: `UPDATE chats SET title=:t, auto_titled=false WHERE
  id=:id AND auto_titled=true`, `rowcount == 0` → тихий пропуск (ручной
  rename выиграл гонку). Возвращает новый title или None. Системное сообщение
  НЕ пишется (тихое переименование — прецедент 013-append тоже без системной
  строки). Сервис не импортирует `app.ws.hub` (grep-пин review F-5).
- `app/ws/autotitle.py` — планировщик (общий для обеих точек): in-flight
  гвард, `to_thread`, fan-out готового `chat_renamed` события (контракт не
  меняется); вызывается из `app/ws/router.py` и
  `app/api/v1/endpoints/chats.py` `create_message`.

Фронт (две дельты на готовых швах):

- `handleChatRenamedEvent` (chats/controller.ts) гасит `auto_titled` в слайсе
  при любом `chat_renamed` (в т.ч. identical-title — LLM могла вернуть текущий
  заголовок, но флаг сервер уже погасил). Заголовок-инпут становится h2.
- AI-чат рождается `auto_titled: true`: страница ассистента → контроллер →
  порт (`auto_titled?: boolean`) → own-адаптер (payload только выставленным —
  зеркало `chats/api/own.ts`).

## Риски и как они закрыты

| Риск | Закрытие |
| --- | --- |
| Гонка LLM-rename vs ручной rename | CAS `WHERE auto_titled=true` + rowcount; ручной rename уже гасит флаг в той же транзакции (013) |
| «Привет-чат» получает глупое название | двухслойный гейт: порог по юзерским репликам + право модели ответить NONE |
| Модель недоступна | фоново, connect-таймаут ~5с, ошибки логируются и глотаются; ретрай — на следующем сообщении; kill-switch CHATTY_AUTOTITLE_ENABLED |
| Дубли вызовов при быстрой переписке | per-process in-flight set + CAS-финал |
| 013-append перезаписывает свежий LLM-титул (участник добавлен в секундное окно вызова модели) | принято как деградация (ревью F-3): окно узкое, исход — механическое название, обратная гонка (LLM поверх ручного rename) исключена CAS |
| Вечные попытки в чате-приветствий | хвостовой гвард MAX_CHAT_MESSAGES=40 |
| Латентность отправки сообщения | триггер после persist/broadcast, fire-and-forget (asyncio.create_task) |

## Non-goals (кратко)

Повторные/плановые переименования; нейминг ручных чатов и DM; персистентный
счётчик попыток (без миграций — их нет вовсе); хардинг 013-append-гонки сверх
задокументированной деградации; изменение контракта WS-событий; правка механики
инпута в messenger.ts; замена 013-дописывания имён; compose-редеплой в этом
пакете.
