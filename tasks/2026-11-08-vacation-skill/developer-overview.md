# Developer overview — 2026-11-08-vacation-skill

## Зачем

Ассистент мессенджера обязан отвечать на «когда мой отпуск?» своими
данными из корпоративного графика, а не генерацией LLM и не RAG-чанками
(уже был инцидент: график в RAG «прилетал» почти к любому вопросу —
комментарий у порога RAG в `backend/app/services/bot.py`). Флоу оператора:
мягкое предложение на общую тему отпуска, немедленный ответ на явный
вопрос про график, фамилия спрашивается один раз и живёт в БД.

## Что увидит юзер

Бот в AI-чате: (а) на общий вопрос про отпуск — «Хотите узнать свои
даты по графику отпусков?»; (б) на «да» — либо даты, либо вопрос о
фамилии с последующим ответом; (в) на явный «график отпусков» — сразу
даты; (г) на «нет» — обычный ответ ассистента на исходный вопрос;
(д) на чужой отпуск — «только по вашим датам». Формат данных:
«Сибгатуллин И.Р. с 21.12.2026 на 7 дней» (несколько периодов —
несколько строк), финальную формулировку делает LLM, при её недоступности
— тот же шаблон.

## Архитектурные границы

Всё изменение — бэкенд, один новый пакет + один хук:

  (`vacation_settings_from_env()`: `CHATTY_VACATION_DATA_DIR`,
  `CHATTY_VACATION_FILE_GLOB`, `CHATTY_VACATION_DIALOG_TTL_SECONDS`;
  паттерн frozen-dataclass как `app/bot/config.py`, ядро
  `app/core/config.py` не трогаем), `parser.py` (openpyxl `read_only`,
  портирование проверенного на реальном файле парсера из

  департмент-строки только с A, даты-«зоопарк» — datetime-ячейки,
  `'15/06/2026'`, `'21.09.'`, `'15.06'`, год усечённых из имени файла),
  `service.py` (`VacationService`: матчинг фамилии токен-точным
  сравнением с нормализацией ё/е и регистра, неоднозначность → список

  рабочая конструкция `\bотпуск(?:…суффиксы)?\b` отсекает глагольные
  продолжения «отпускает»), `skill.py` (машина состояний
  `awaiting_yes` / `awaiting_surname` с cancel-словами, повторным
  предложением и рекавери устаревшей фамилии), `prompts.py`
  (LLM-формулировка из структурированных строк, без RAG-чанков).

## Модель исполнения и риски

Две последовательные волны, один исполнитель на волну:
WS-BE-DATA (хранилище+парсер+ингест+lookup) → WS-BE-FLOW (интент,
машина состояний, хук бота, LLM-формулировка, приватность, тесты
диалогов). Риски: (1) «грязные» даты реального графика — прикрыты
парсером, проверенным на живом файле, + фикстура со ВСЕМИ форматами;
(2) ложные срабатывания ключевых слов — морфологический регекс с
исключениями глагольных форм, негативные пины; (3) личные данные —
xlsx не коммитится, фамилии в БД, только свои даты; (4) зависимость
от живой LLM — весь автотест на FakeBotProvider, живой смоук AC-LIVE
блокирует финал (бот сейчас недоступен — решение оператора держать PR).
