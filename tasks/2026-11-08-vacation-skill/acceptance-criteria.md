## AC-PARSE — парсер «грязного» графика (EV-1)

Синтетическая xlsx-фикстура (openpyxl в tmp_path) воспроизводит
реальный зоопарк: 2 листа-отдела, шапка A1:E1, департмент-строка
(только A), даты как datetime-ячейка, строки `'15/06/2026'`,
`'21.09.'`, `'15.06'`, `'DD.MM.YYYY'`, пустые/пробельные ячейки,
строки с ФИО без дат, год усечённых дат из имени файла
`график отпусков 2027.xlsx` (fallback — текущий год). Пины: точные
значения start_date/days/full_name/department каждой строки;
undated-строки — в skipped со счётом, в rows их нет.

## AC-RUNBOOK — инструкция обновления совпадает с реальностью (EV-2)

`docs/deployment/vacation-schedule.md` существует и описывает:

команда ранбука совпадает с фактически реализованными флагами CLI.

## AC-LOOKUP — матчинг и форматирование (EV-1)

`VacationService.find`: ПОЛНОЕ нормализованное ФИО («Гончаров А.Б.»)
резолвится однозначно среди двух Гончаровых (равенство полной строки
пробуется первым — бот сам просит инициалы при коллизии, F-R2-2);
точная фамилия (токен-равенство) → уникальный человек с
отсортированными периодами; «Романов» НЕ матчит «Романову К.В.»
(правило D-7 — НЕ порт substring-логики vacation_query.py);
голая фамилия при двух носителях → список кандидатов
(префикс-направление: и «Гончар» тоже); несуществующая фамилия →
difflib-подсказки («Сибгатуллина» → подсказка). Нормализация:
регистр, ё→е. `format_periods`: «Сибгатуллин И.Р. с 21.12.2026 на
7 дней», «на 1 день», «на 14 дней», «на 24 дня» (склонение),
периоды отсортированы по дате.

## AC-INTENT — классификатор (EV-3)

`classify`: «Хочу в отпуск» → vacation; «Когда у меня отпуск по
графику?» / «покажи график отпусков» / «мои даты по графику» →
schedule (приоритет над vacation); «меня не отпускает задача» /
«отпустите меня с собрания» → None (конструкция
`\bотпуск(?:а|у|е|ом|и|ов|ам|ах)?\b` — глагольные продолжения не
могут замэтчиться, F-3); словари yes/no/cancel — точное словарное
совпадение после нормализации: «ДА» → yes (регистронезависимость),
«дада» → None (правила схлопывания повторов букв нет и не нужно);
«как погода?» → None.

## AC-FLOW — семь диалоговых сценариев через бота, FakeBotProvider (EV-3)

Сквозные сценарии в AI-чате (app+client из conftest,
`app.state.bot_provider` = FakeBotProvider, sqlite):

1. «Хочу в отпуск» → ответ бота — предложение «Хотите узнать свои
   даты по графику отпусков?», LLM-путь не вызывался (0 вызовов
   FakeBotProvider.complete для этого рана);
1b. «да» ПРИ СОХРАНЁННОЙ фамилии → сразу ответ с датами, вопрос о
   фамилии не задан (F-13);
2. «да» без фамилии → вопрос о фамилии; «Сибгатуллин» → ответ
   содержит все три периода, `vacation_names` содержит каноническое
   ФИО; НОВЫЙ чат, «Когда у меня отпуск по графику?» → немедленный
   ответ БЕЗ вопроса о фамилии (персистентность, stateless-раны);
3. «Когда у меня отпуск по графику?» с нуля (фамилии нет) → сразу
   вопрос о фамилии, предложения не было;
4. «нет» на предложение → обычный путь: complete вызван РОВНО один
   раз и в его промпте — ИСХОДНЫЙ вопрос, не слово «нет»;
5. постороннее НЕ-отпускное сообщение в ожидании да/нет → сброс
   состояния, обычная обработка; повторный отпускной вопрос в
   ожидании → ПОВТОРНОЕ предложение с обновлённым origin (F-7);
   cancel-слова на любом шаге → короткий ack и выход БЕЗ сжигания
   попытки;
6. два неудачных ввода фамилии → после второго подсказки + вежливый
   выход, состояние сброшено; TTL: протухшее состояние ведёт себя
   как отсутствие;
7. устаревшая фамилия: сохранённое имя исчезло из реингестнутого
   снимка → бот удалил фамилию из БД, сообщил «график обновился» и
   переспросил один раз в том же флоу (D-15).

## AC-LLMFMT — LLM-формулировка с фолбэком (EV-3)
