# Decisions — 2026-11-08-vacation-skill

Журнал решений контроллера. Кларификации оператора сняты 2026-11-08
(четыре ответа), остальное — замещения по делегации «Используй alk».

## D-1 — роль LLM: гибрид (кларификация оператора)

Оператор выбрал гибрид: детерминированный флоу (ключевые слова + машина
состояний) и данные из парсера xlsx, а LLM формулирует финальный ответ
из структурированных строк; при недоступности LLM — готовый шаблон.
Отвергнуто: tool-calling (в `app/bot/provider.py` нет tools — только
текстовая генерация; поведение модели Ollama без живого бота не
проверить) и «чистые шаблоны без LLM» (нет связки с файлом, смысл
запроса оператора). RAG-путь для графика запрещён: живой инцидент
«график прилетал к любому вопросу» уже был (комментарий в
services/bot.py).

## D-2 — только свои даты (кларификация оператора)

Lookup идёт ТОЛЬКО по сохранённой фамилии юзера либо по фамилии,
введённой в ответ на прямой вопрос бота о СВОЕЙ фамилии. Запрос
про третьих лиц («когда отпуск у Иванова») маршрутизируется в
предложение своих дат, прямой поиск по чужой фамилии технически
отсутствует. Приватность закреплена отдельным REQ-PRIVACY.

## D-3 — PR держится до живой проверки (кларификация оператора)

Оператор выбрал «держать PR до живой проверки»: автоматические
критерии закрываются моками (FakeBotProvider), но финальный аудит без
живого диалогового смоука на поднятом compose+Ollama-стеке возвращает
BLOCKED (внешнее ожидание по cookbook), PR в dev не мержится до
прохождения AC-LIVE. Бот сейчас недоступен — прогон может
приостановиться в BLOCKED и продолжиться событием оператора.

## D-4 — данные: гитигнорённый data-dir + ингест в БД (кларификация оператора)

xlsx с реальными ФИО не коммитится (репо публичный): оператор кладёт
файл в `backend/data/` (запись в корневом `.gitignore`), CLI-ингест
парсит в таблицы-снимки, реингест того же года заменяет снимок.
Отвергнуто: чтение xlsx на лету (парсинг на каждый запрос, нет
SQL-истории) и коммит файла (личные данные в git-истории навсегда).
Фамилии юзеров ссылаются на канонические ФИО из графика, а не на id
строк — реингест их не ломает.

## D-5 — стейт диалога в БД, стейт один на юзера

Раны stateless (ключ `message_id`), рестарты API теряют память —
стейт живёт в `assistant_dialog_state` (PK user_id). Ключ именно
user_id, не (user_id, chat_id): флоу персональный, вопрос «ваша
фамилия» не задаётся дважды в разных чатах. TTL 10 минут
(`CHATTY_VACATION_DIALOG_TTL_SECONDS`): протухшее «да» не должно
цепляться к новой теме. Постороннее сообщение в ожидании — сброс
состояния, обычная обработка.

## D-6 — «нет» на предложение = обычный ответ на исходный вопрос

Предложение не является ответом: при отказе бот выполняет обычный
RAG+LLM путь с ИСХОДНЫМ вопросом (state хранит origin_content), а не
с сообщением «нет». Иначе юзер, отказавшийся от своих дат, терял бы
ответ на сам вопрос («как оформить отпуск?»).

## D-7 — матчинг фамилии: полное ФИО, потом токен-точность, потом кандидаты (уточнено round 2)

Введённая строка СНАЧАЛА сравнивается на равенство ПОЛНОГО
нормализованного ФИО (все токены — «Вишневский А.А.» резолвится
однозначно, бот сам просит инициалы при коллизии однофамильцев,
F-R2-2); затем — ТОЧНОЕ равенство первого токена (фамилии)
канонического ФИО после нормализации (lower, ё→е, без точек):
«Свеклов» → только «Свеклов Н.Н.», НЕ «Свеклова Е.Е.». Только при
нулевом точном сходстве — префикс как кандидаты со списком
уточнения. difflib-подсказки при полном промахе. Правило НОВОЕ и
строже substring-логики `tasks/RAG-docs/vacation_query.py`
(портирован только парсер).

## D-8 — периоды без дат не хранятся

Строки графика с ФИО, но без даты/дней, не попадают в БД: они
считаются в `skipped`-сводке ингеста (прозрачность для оператора),
но в ответе бота не упоминаются — «ещё 1 период(а) без дат» в чате
мессенджера шумит. Дата→вопросы юзера касаются только назначенных
периодов.

## D-9 — ложные срабатывания интента (конструкция уточнена D-14)

Морфологический регекс «отпуск…» исключает глагольные корни
(«отпусти/отпустите/отпускает/отпустить…»): «меня не отпускает задача»
не должно предлагать график. Да/нет — закрытые словари с нормализацией
(регистр, «даа», «ок/окей»). Явная ветка графика («график отпусков»,
«мои даты по графику», «когда мой отпуск») — приоритетнее общей.

## D-10 — LLM-формулировка без RAG-чанков и без стриминга

Промпт скилла содержит только структурированные периоды + правило
«не выдумывай дат»; RAG-чанки в него не подмешиваются (данные уже
верные). Вызов небыстрый `complete()` без стриминга: Ollama-провайдер
и так не стримит (`complete_stream` = один чанк), а SSE-мост
`bot_delta` остаётся общим для обычного пути. Ошибка/таймаут
провайдера → шаблонный ответ из тех же строк (бот отвечает всегда).

## D-11 — бэкенд-гейт стенда (наследие mobile-ux)

`npm run verify:backend` на Windows-стенде не резолвится; канонический
вызов — `PYTHON_BIN=<backend-venv-python> bash backend/verify.sh`
(точный путь стенда — в операторском runbook и логе evidence).
Вердикт PASS: всё зелёное, КРОМЕ ровно 4 известных POSIX-only падений
`tests/unit/ingestion/test_converter.py` (WinError 193, идентичны
до/после, вне write-set), ноль новых падений, ноль удалённых тестов,
полный вывод до/после в evidence. Новые тесты vacation-скилла обязаны
проходить на Windows (без soffice-зависимостей).

## D-12 — коммиты

Conventional commits, БЕЗ co-author-строк (правило оператора,
см. память прогона). Пакет плана коммитится, `work/` и `.alk/` — нет.

## D-13 — постоянный механизм обновления графика + ранбук (запрос оператора, 2026-11-08)

Оператор: «файл с графиками нужно будет обновлять в базе, продумай
постоянный механизм и напиши инструкцию». Механизм = идемпотентный
CLI `scripts/ingest_vacations.py` (запуск venv-интерпретатором
бэкенда стенда — глобальный py -3.12 не имеет
sqlalchemy/pydantic-settings, F-R2-3) с флагами `--file`/`--db`
(оверрайд строки БД — ингест с хоста против compose-Postgres по
операторскому env, без правок compose) + семантика «тот же год —
полная замена снимка, новый год — рядом» (фамилии в отдельной
таблице и реингест переживают). Инструкция =
`docs/deployment/vacation-schedule.md` (конвенция docs/deployment/):
стейджинг файла, команда, семантика, проверка, откат, поведение при
исчезновении человека. Отвергнуто: cron/авто-реингест (ручная
операторская команда детерминированнее; в non-goals), чтение xlsx
на лету (см. D-4).
